# CoDrive 디자인 테마 가이드

**테마: Black & Cream · 버전 1.7 · 기준일 2026-11-15**

CoDrive의 다른 화면을 디자인하거나 구현할 때 사용하는 공통 기준입니다. Pleos Connect 센터콘솔과 자연스럽게 어울리도록, 어두운 메뉴·현재 경로 영역과 따뜻한 크림색 콘텐츠 영역을 조합합니다. 현재 함께 조정한 [AI 경로 추천 HTML](route-recommendation.html)을 기준 화면으로 삼습니다.

이 문서는 현재 HTML 디자인을 정리한 프로젝트 가이드입니다. Android 앱은 동일한 HTML을 내부 WebView에 포함하고 기기 음성 입력을 Java 코드로 연결합니다. Pleos 공식 규격의 적합성을 판정하는 문서는 아닙니다. 아래 수치는 별도 표기가 없으면 HTML의 CSS px 기준입니다. 앱의 WebView는 화면 밀도와 시스템 글자 배율을 반영합니다.

## 1. 디자인 방향

- **색상은 차분하게 사용합니다.** 크림색 배경, 웜화이트 표면, 짙은 글자색으로 정보의 위계를 만듭니다.
- **첫 화면에는 필요한 것만 둡니다.** 사용자가 지금 할 행동을 먼저 보여주고, 설명과 결과는 해당 상태에서 표시합니다.
- **대화와 입력은 둥글게 연결합니다.** 프롬프트와 대화 말풍선은 같은 곡률을 사용합니다.
- **보조 정보는 작고 가볍게 둡니다.** 위치, 그룹원, 자동 결정 안내에 각각 큰 카드를 만들지 않습니다.
- **모션은 상태 변화를 설명합니다.** 누름, 전환, 입력 중, 로딩, 응답 완료를 부드럽게 연결합니다.

새 화면에서도 큰 홍보 문구, 반복되는 기능 설명, 강한 그라데이션, 네온 색상, 과한 그림자와 장식용 AI 아이콘은 추가하지 않습니다. 핵심 기능은 배치와 명확한 문구로 드러냅니다.

색상 이름은 역할을 기준으로 사용합니다. 화면마다 비슷한 크림색이나 회색을 새로 만들지 않습니다. 그룹원처럼 옅게 보여야 하는 글자에도 지정된 보조 글자색을 사용하고, 임의로 투명도를 더 낮추지 않습니다.

현재 HTML의 핵심 색상 변수는 다음과 같습니다.

```css
:root {
  color: #24221e;
  background: #f3f0e9;
  --accent: #24221e;
  --on-accent: #fffdf8;
  --muted: #706c64;
  --line: #d7d1c7;
  --surface: #fffdf8;
  --message-radius: 41px;
}
```

## 3. 글자와 아이콘

글꼴은 시스템 산세리프를 사용합니다. 현재 HTML은 `-apple-system`, `BlinkMacSystemFont`, `Segoe UI`, `Malgun Gothic`, `sans-serif` 순서입니다. 별도 장식용 글꼴을 추가하지 않습니다.

| 용도 | 크기 | 굵기·줄 높이 |
| --- | --- | --- |
| 빈 대화의 질문 제목 | 26~34px | 600, 줄 높이 1.4 |
| 일반 화면 제목 | 28px | 600 |
| 그룹 이름 | 24px, 창 너비 1100px 이하에서 22px | 600 |
| 프롬프트 입력 | 22px, 창 너비 600px 이하에서 20px | 400, 줄 높이 1.6 |
| 사용자 메시지 | 20px | 400, 줄 높이 1.6 |
| AI 답변 제목 | 22px | 600 |
| AI 답변 본문·버튼·안내 | 18px | 본문 줄 높이 1.6, 토글 안내 1.4 |
| 그룹원 | 16px | 400, 줄 높이 1.4 |
| 현재 경로 제목 / 장소명 / 보조 정보 | 20px / 20px / 16px | 각각 600 / 500 / 400, 장소 줄 높이 1.5 |

아이콘은 선형 스타일로 통일합니다. 기본 크기는 24×24px, 선 두께는 1.7px, 선 끝과 연결부는 둥글게 처리합니다. 위치 아이콘은 20×20px입니다. 이모지와 서로 다른 두께의 아이콘을 섞지 않습니다.

아이콘만 있는 버튼에도 접근성 이름을 제공합니다. 예: 마이크는 `음성으로 입력하기`, 전송은 `경로 추천받기`, 녹음 중 마이크는 `음성 입력 취소`입니다.

## 4. 간격과 모양

간격은 현재 사용 중인 4·8·12·16·20·24·28·32·40px를 우선 재사용합니다. 화면별로 조금씩 다른 여백을 만들기보다 역할이 같은 요소의 간격을 맞춥니다.

| 요소 | 기준 |
| --- | --- |
| 프롬프트·사용자 말풍선·AI 말풍선·경로 확인 팝업 곡률 | 모두 41px |
| 원형 마이크·전송 버튼 | 64×64px, 곡률 50% |
| 예시 프롬프트 카드 | 높이 최소 64px, 너비 최소 260px, 캡슐형 |
| 모드 선택 외곽 / 내부 버튼 곡률 | 8px / 5px |
| 사이드 메뉴 항목 곡률 | 6px |
| 일반 입력·보조 버튼 곡률 | 6px |
| 그룹 생성 패널 곡률 | 8px |
| 기본 테두리 | 1px |
| 일반 버튼 최소 높이 | 64px |
| 토글 조작 영역 / 보이는 트랙 / 손잡이 | 52×48px / 52×30px / 22×22px |

대화·입력의 큰 곡률과 탐색·설정 컨트롤의 작은 곡률을 구분합니다. 모든 패널을 캡슐형으로 바꾸지 않습니다. 큰 그림자 대신 표면색과 얇은 경계선으로 영역을 구분합니다.

## 5. 화면 배치

### 공통 골격

- 왼쪽부터 어두운 탐색 영역, 어두운 현재 경로 패널, 크림색 메인 영역 순서로 배치합니다. 경로 정보는 왼쪽 운전석과 가까운 쪽에 둡니다.
- 왼쪽 메뉴 바로 옆 경로 패널의 너비는 280px, 내부 여백은 위아래 32px·좌우 24px입니다.
- 상단 오른쪽에 개인·그룹 모드 선택을 둡니다. 그룹 정보는 상단 왼쪽에 둡니다.
- 주 콘텐츠는 최대 너비 1040px로 가운데 정렬합니다.
- 기본 메인 여백은 위 28px, 좌우 40px, 아래 24px입니다.
- 창 너비 1100px 이하에서는 사이드 메뉴를 220px에서 80px로 줄이고 아이콘 중심으로 표시합니다. 메인 여백은 24px이며, 경로 패널 너비는 220px·내부 여백은 위아래 28px·좌우 20px입니다.
- 창 너비 760px 이하에서는 경로 패널을 메인 영역 아래로 옮깁니다. 높이는 최대 화면의 32%이며, 긴 경로는 패널 안에서 스크롤합니다.
- 창 너비 600px 이하에서는 사이드 메뉴를 숨기고 메인 여백을 위아래 20px, 좌우 16px로 줄입니다.

기준 검수 크기는 전체 창 **1682×1210**, 분할 창 **829×1210**입니다. 이는 현재 검수 도구의 설정값이며, 다른 창 크기에서도 콘텐츠가 부모 영역에 맞춰 줄어들어야 합니다.

### 추천 화면의 상태별 배치

| 상태 | 배치와 표시 |
| --- | --- |
| 대화 없음 | 프롬프트 전체를 메인 영역 가운데에 놓고, 바로 위에 질문과 흐르는 예시 카드를 표시 |
| 첫 요청 전송 | 질문·예시를 숨기면서 프롬프트를 아래로 이동 |
| 대화 있음 | 위에는 스크롤 가능한 대화 기록, 아래에는 입력 영역 유지 |
| 개인 모드 | 상단 왼쪽 그룹 정보 숨김 |
| 그룹 모드 | 왼쪽 위에 그룹 이름·차량 수, 그 아래 그룹원 표시 |
| 그룹 없음 | 그룹 생성 화면으로 이동하고 그룹 추천 전송 차단 |
| 안내 중인 경로 있음 | 개인·그룹 모드에 관계없이 현재 위치부터 남은 경유지·목적지를 경로 패널에 표시 |
| 안내 중인 경로 없음 | 경로 패널에 `안내 중인 경로가 없어요` 표시 |

개인 모드의 메인 상단에 `AI 경로 추천` 제목을 다시 넣지 않습니다. 빈 대화의 질문은 `어디로 가고 싶나요?`입니다.

## 6. 컴포넌트 규칙

### 프롬프트 입력

한 줄 입력창을 사용합니다. 입력 영역, 원형 마이크, 원형 오른쪽 화살표를 하나의 둥근 프롬프트 영역에 배치합니다.

- 바깥 여백: 위·아래·오른쪽 8px, 왼쪽 24px.
- 입력과 버튼 묶음 사이 간격: 12px. 마이크와 전송 사이: 8px.
- 입력란 높이: 64px. 기본 전체 높이: 테두리를 포함해 82px.
- 플레이스홀더: `가고 싶은 곳이나 코스를 입력하세요`.
- 포커스가 들어오면 바깥 테두리를 주요 글자색으로 바꿉니다.
- 마이크에 `음성 입력`, 전송에 `추천` 같은 글자를 붙이지 않습니다.
- 공백뿐인 입력은 전송하지 않습니다. 전송한 뒤 입력란은 비웁니다.

### 위치와 경로 자동 결정

위치는 프롬프트 왼쪽 바로 아래에 위치 아이콘과 장소명만 표시합니다. 별도의 테두리와 `위치 예시` 같은 제목은 넣지 않습니다.

자동 결정은 프롬프트 오른쪽 아래에 토글과 짧은 안내만 둡니다. 위치 정보와 비슷한 높이의 가벼운 보조 영역으로 취급합니다. 안내를 큰 카드로 감싸거나 설명 전체를 클릭 영역으로 묶지 않습니다.

| 토글 상태 | 안내 문구 | 전송 후 동작 |
| --- | --- | --- |
| OFF | 추천 경로를 직접 선택해요. | 추천 장소 목록을 보여주고, 장소를 선택하면 2초 반영 로딩 후 그곳을 목적지로 설정 |
| ON | 최대한 빠르게 경로를 설정해줘요. | 답변 로딩 3초 후 반영 로딩 2초를 거쳐 추천 장소 3곳을 잇는 경로를 자동 반영 |

토글만 클릭해 켜고 끌 수 있으며, 손잡이를 드래그해도 바뀝니다. 드래그 중에는 손잡이가 포인터를 따라가고, 놓으면 가까운 상태로 부드럽게 정착합니다. 안내 문구는 같은 자리에 겹쳐 놓고 교차 페이드합니다.

동작 기준은 요청을 보낸 순간의 토글 상태입니다. 전송 후 토글을 바꾸더라도 이미 보낸 요청의 동작은 바뀌지 않습니다. OFF 요청은 기존 경로를 유지하며, 새 ON 요청은 답변·반영 로딩이 끝나면 경로를 바꿉니다. 자동 설정 대기 중 사용자가 직접 장소를 선택하면 그 선택을 우선합니다.

다른 모드에서 설정한 경로가 이미 있으면 경로 반영 전에 아래의 변경 확인 팝업을 거칩니다. 단순히 개인·그룹 버튼을 바꾸거나 OFF 추천 목록을 받는 것만으로는 팝업을 띄우지 않습니다.

### 마이크

기본 상태는 선형 마이크 아이콘입니다. 입력을 받는 동안에는 어두운 원형 배경과 밝은 파형 5개를 표시합니다. 파형은 높이가 잔잔하게 변합니다.

말이 끝나고 최종 인식 결과가 확정되면 자동 전송합니다. 녹음 중 다시 누르면 취소합니다. 취소나 인식 오류가 발생하면 녹음 전 초안을 보존합니다. 모드 전환 시에는 진행 중인 음성 입력을 취소합니다.

### 흐르는 예시 프롬프트

빈 대화에서 질문 아래, 프롬프트 위에 한 줄로 배치합니다. 예시 카드는 회전초밥처럼 오른쪽에서 왼쪽으로 끊김 없이 흐릅니다.

- 아이콘과 짧은 문구를 담은 캡슐형 카드를 사용합니다.
- 카드 간격은 12px, 내부 여백은 위아래 14px·좌우 20px입니다.
- 양쪽 끝 28px는 서서히 흐려지게 처리합니다.
- 카드에 마우스를 올리거나 키보드 포커스를 두거나 누르는 동안 이동을 멈춥니다.
- 카드를 누르고 떼면 해당 문장을 입력란에 넣고 **즉시 전송**합니다.
- 대화가 생기면 예시 영역을 숨기고 이동을 멈춥니다.
- 연속 이동을 위해 복제한 카드는 중복된 키보드 탐색·스크린리더 항목으로 노출하지 않습니다.

### 대화와 AI 답변

사용자 메시지는 오른쪽에 정렬합니다. 너비는 내용에 맞추되 대화 영역의 90%를 넘지 않게 합니다. 창 너비 600px 이하에서는 최대 100%까지 허용합니다.

AI 답변은 그 아래 밝은 표면에 표시합니다. 두 말풍선 모두 내부 여백은 위아래 24px·좌우 32px이며 곡률은 프롬프트와 같은 41px입니다. 요청과 답변 사이는 16px, 다음 대화 묶음까지는 28px를 둡니다.

답변 영역은 먼저 로딩 상태로 나타나고, 준비가 끝나면 본문이 아래에서 올라오며 표시됩니다. 로딩 문구는 `답변을 준비하고 있어요.`입니다. 현재 HTML의 3초 대기는 시연용입니다. 실제 AI를 연결할 때는 응답 준비 상태에 맞춰 전환하며, 디자인을 맞추기 위해 3초를 강제로 기다리지 않습니다.

입력 문구와 무관하게 아래 더미 데이터 3개를 사용합니다. 타이핑·음성·예시 카드 전송 모두 같은 결과를 냅니다.

| 장소 | 표시할 설명 |
| --- | --- |
| 대청호 산책로 | 산책 · 물가를 따라 가볍게 걷기 좋은 곳 |
| 호숫가 식당 | 식사 · 드라이브 중 편하게 들를 식사 장소 |
| 전망 카페 | 카페 · 풍경을 보며 쉬어갈 수 있는 곳 |

OFF 답변의 제목은 `추천 장소`입니다. 각 장소는 이름·설명·오른쪽 화살표가 있는 목록 행으로 표시하며, 행 전체를 눌러 선택합니다. 별도의 큰 카드 테두리는 추가하지 않습니다. ON 답변의 제목은 `추천 경로`이며, 세 장소를 방문 순서대로 보여줍니다. 로딩 중에는 목록을 선택할 수 없습니다.

개인 대화와 그룹별 대화는 분리합니다. 모드를 바꾸면 해당 대화를 복원합니다. 긴 메시지는 줄바꿈하고, 입력창을 밀어내지 않도록 대화 영역 안에서 스크롤합니다.

### 개인·그룹 선택과 그룹 정보

모드 선택은 얇은 테두리 안의 두 버튼으로 구성합니다. 선택된 버튼은 어두운 배경과 밝은 글자, 나머지는 투명 배경과 보조 글자색입니다.

그룹 정보는 다음 순서로 표시합니다.

```text
강릉 주말 여행   차량 3대
나 · 민수 · 지연
```

그룹 이름은 주요 글자색과 굵기 600, 그룹원은 그 아래 6px 간격으로 보조 글자색·16px를 사용합니다. 그룹원 이름은 현재 시연 데이터이며 실제 서비스에서는 참여자 데이터로 바꿉니다.

그룹 선택 시 왼쪽에서 페이드 인하고, 개인 선택 시 왼쪽으로 이동하며 페이드 아웃합니다. 나가는 동안 글자를 먼저 지우지 않습니다. 빠르게 모드를 바꿔도 현재 위치에서 전환을 이어가며, 선택 버튼과 입력 영역이 갑자기 밀리지 않도록 합니다.

### 현재 경로 패널

왼쪽 메뉴 바로 옆 검은 영역은 실제로 안내 중인 경로를 보여주는 공통 영역입니다. 제목은 `현재 경로`이며, 출처는 `내비게이션 경로` 또는 `추천받은 경로`로 구분합니다.

`현재 경로` 제목 바로 아래에 경로의 소속을 표시합니다. 개인 경로는 `개인`, 그룹 경로는 `강릉 주말 여행`처럼 해당 그룹의 별칭을 사용합니다. 제목 글자와 왼쪽을 맞추고, 위 간격 8px·18px 보조 글자색 `#AAA7A0`로 가볍게 표시합니다. 별도의 테두리나 배지는 붙이지 않습니다. 현재 보고 있는 개인·그룹 탭과 관계없이 실제 설정된 경로의 소속을 유지합니다. 경로가 없거나 2초 반영 로딩 중에는 소속 표시를 숨기며, 변경 확인 중에는 기존 경로의 소속을 유지합니다. 새로고침 후에도 그룹 별칭을 복원합니다.

현재 위치를 맨 위에 놓고, 남은 경유지를 거쳐 목적지까지 세로 선으로 연결합니다. 현재 위치는 밝은 원과 바깥 고리, 경유지는 빈 원, 목적지는 깃대가 있는 밝은 선형 깃발 아이콘으로 구분합니다. 깃발은 24×24px, 선 두께 1.7px로 다른 아이콘과 맞춥니다. 장소명은 밝게, `현재 위치`·`경유지 1`·`목적지` 같은 보조 정보는 옅게 표시합니다. 이미 지난 지점은 남은 경로 목록에 포함하지 않습니다.

안내 중인 경로가 없으면 위치 아이콘과 `안내 중인 경로가 없어요`만 표시합니다. 이 문구는 차량이 정차했다는 뜻이 아니며, 목적지 설정 없이 이동 중인 경우에도 같습니다.

OFF 상태의 추천 결과만으로 안내 경로를 바꾸지 않습니다. 사용자가 장소를 직접 선택하거나 ON 요청의 답변 로딩이 끝나면 경로 반영을 시작합니다. 현재 경로 패널에 점 3개의 로딩 효과와 `네비게이션에 반영중입니다`를 2초간 표시하고, 완료되면 경로를 보여줍니다. 반영 중에는 빈 상태 안내와 기존 경로 목록을 숨깁니다. 개인·그룹 전환과 과거 답변 복원은 현재 경로를 바꾸지 않습니다. 실제 내비게이션을 연동한 경우에는 활성 안내 경로를 반영합니다.

현재 HTML은 실제 내비게이션과 연결하지 않은 시연입니다. 처음에는 현재 경로를 비워두고, 프롬프트 전송과 장소 선택으로 상태를 확인합니다. 이전의 경로 미리보기 선택기는 제거했습니다. 검수 도구의 `대화·경로 초기화`로 처음 상태로 되돌립니다.

ON으로 설정되는 모의 경로는 현재 위치 `대전 유성구`, 경유지 `대청호 산책로`·`호숫가 식당`, 목적지 `전망 카페` 순서입니다. OFF 목록에서 선택하면 현재 위치에서 선택한 한 장소까지 표시합니다. 선택한 경로와 자동 설정·반영 로딩의 남은 대기 시간은 같은 브라우저 탭의 세션에 보관하며 새로고침해도 복원합니다. 시연은 실제 내비게이션을 변경하지 않습니다.

### 다른 모드의 경로 변경 확인

현재 경로가 개인에서 설정되었는데 그룹에서 새 경로를 설정하거나, 그룹에서 설정되었는데 개인에서 바꾸려 하면 확인 팝업을 표시합니다. 경로의 소속은 요청을 보낸 모드로 기록합니다. 로딩 중 화면의 모드를 바꾸어도 요청의 소속은 바뀌지 않습니다. 같은 모드의 경로를 바꾸거나 기존 경로가 없으면 확인 팝업 없이 2초 반영 로딩을 진행합니다.

ON은 답변 로딩 3초가 끝난 시점, OFF는 추천 목록에서 장소를 선택한 시점에 확인합니다. 팝업이 떠 있는 동안 기존 경로를 유지합니다.

| 요소 | 문구·동작 |
| --- | --- |
| 제목 | 이미 경로가 설정되어 있어요. |
| 본문 | 현재 경로를 취소하고 새 경로로 설정할까요? |
| 타이머 안내 | 10초 후 새 경로로 자동 변경해요. 숫자는 남은 초로 갱신 |
| 새 경로 수락 | 팝업을 닫고 2초 반영 로딩 후 새 경로 표시 |
| 거절 | 타이머를 취소하고 기존 경로 유지 |
| 10초 만료 | 수락과 같은 동작으로 새 경로 반영 |
| Escape | 거절과 같은 동작 |

화면 가운데에 최대 너비 560px, 내부 여백 32px의 웜화이트 팝업을 둡니다. 곡률은 41px입니다. 배경은 어둡게 덮고, `거절`은 밝은 보조 버튼, `새 경로 수락`은 어두운 주요 버튼으로 표시합니다. 두 버튼의 최소 높이는 64px입니다.

기본 모달 대화상자를 사용해 배경 조작을 막고 키보드 포커스를 팝업 안에 유지합니다. 처음 포커스는 거절 버튼에 둡니다. 남은 초는 한 자리에서 바뀌는 숫자로 표시하며, 매초 별도 음성 알림을 반복하지 않습니다. 새로고침해도 남은 시간을 이어가며 10초를 처음부터 다시 세지 않습니다. 거절한 요청은 나중에 자동 적용되지 않습니다.

## 7. 모션 기준

주요 이동의 감속 곡선은 `cubic-bezier(.22, 1, .36, 1)`입니다. 빠르게 출발해 부드럽게 멈춥니다. 탄성이나 튀어 오르는 효과를 추가하지 않습니다.

| 대상 | 시간·곡선 | 표현 |
| --- | --- | --- |
| 일반 버튼 누름·복귀 | 140ms, ease-out | 누르는 동안 크기 0.96, 밝기 0.94, 가벼운 안쪽 그림자 |
| 토글 손잡이 정착 | 280ms, 주요 감속 곡선 | 양 끝 상태 사이 이동. 드래그 중에는 전환 없이 직접 추적 |
| 토글 배경색 | 220ms, ease-out | OFF·ON 색 전환 |
| 토글 안내 문구 | 180ms, ease-out | 같은 위치에서 교차 페이드 |
| 전송 후 프롬프트 이동 | 520ms, 주요 감속 곡선 | 가운데에서 하단으로 이동 |
| 빈 대화 안내 숨김 | 투명도 180ms, 이동 220ms, ease-out | 위로 6px 이동하며 사라짐 |
| 대화 영역 첫 표시 | 240ms, ease-out | 페이드 인 |
| 경로 상태 표시 | 240ms, ease-out | 빈 경로 또는 활성 경로 영역 페이드 인 |
| 경로 반영 로딩 | 2초 표시, 점은 900ms ease-in-out 반복 | 현재 경로 패널에서 반영 안내 후 경로 표시 |
| 경로 확인 팝업 진입 | 240ms, 주요 감속 곡선 | 아래 16px에서 올라오며 페이드 인. 배경 덮개는 180ms 페이드 인 |
| AI 답변 영역 진입 | 420ms, 주요 감속 곡선 | 아래 16px에서 올라오며 페이드 인 |
| 로딩 완료 후 답변 본문 | 420ms, 이동·확장은 주요 감속 곡선, 투명도는 ease-out | 아래 14px에서 올라오며 본문 높이 확장 |
| 그룹 정보 전환 | 투명도 240ms ease-out, 이동 320ms 주요 감속 곡선 | 왼쪽 20px와 원래 위치 사이 전환 |
| 예시 프롬프트 연속 이동 | 한 세트 이동에 28초, linear, 반복 | 일정한 속도로 왼쪽 이동 |
| 녹음 파형·로딩 점 | 900ms, ease-in-out, 반복 | 파형 높이 변화 / 점의 투명도·작은 상하 이동 |

일반 버튼은 누를 때 피드백을 주고 **손을 뗀 클릭 시점에 동작**합니다. 토글 드래그는 놓는 순간 상태를 확정하며, 뒤따르는 클릭으로 두 번 바뀌지 않아야 합니다.

동작 줄이기 설정에서는 전환과 반복 애니메이션을 끕니다. 예시 카드는 움직임 없이 가로 스크롤로 볼 수 있게 합니다. 로딩·녹음 상태는 글자와 형태로 계속 식별할 수 있어야 합니다.

## 8. 문구 원칙

짧고 자연스러운 한국어를 사용합니다. 안내는 `~해요`, 입력 유도는 `~입력하세요`처럼 익숙한 표현으로 씁니다. 사용자가 행동을 결정하는 데 필요한 내용만 표시합니다.

| 상황 | 기준 문구 |
| --- | --- |
| 빈 대화 제목 | 어디로 가고 싶나요? |
| 입력 플레이스홀더 | 가고 싶은 곳이나 코스를 입력하세요 |
| 자동 결정 OFF | 추천 경로를 직접 선택해요. |
| 자동 결정 ON | 최대한 빠르게 경로를 설정해줘요. |
| 답변 로딩 | 답변을 준비하고 있어요. |
| 음성 입력 중 | 듣고 있어요. 말을 마치면 자동으로 전송돼요. |
| 음성 입력 취소 | 음성 입력을 취소했어요. |

기술 용어, 내부 상태명, 장황한 AI 소개를 일반 화면에 넣지 않습니다. 실제로 연결되지 않은 기능의 결과는 시연임을 구분합니다. 현재 추천 결과·위치·그룹 데이터는 예시이며 실제 내비게이션 변경을 뜻하지 않습니다.

## 9. 다른 화면으로 확장하는 방법

색상·글자 위계·아이콘·간격·조작 피드백을 공통으로 가져갑니다. 가운데 프롬프트, 흐르는 예시, 대화의 하단 이동은 추천 화면의 동작이므로 다른 화면에는 필요한 경우에만 적용합니다.

다음은 아직 완성하지 않은 화면을 위한 적용 방향입니다.

| 화면 | 이 테마를 적용할 방향 |
| --- | --- |
| 우리 그룹 | 그룹 이름을 주요 정보로, 참여자는 보조 글자색으로 표시. 목록은 같은 여백과 얇은 구분선 사용 |
| 실시간 주행 | 현재 경로·주행 상태를 먼저 배치. 보조 정보는 웜화이트 표면과 보조 글자색으로 구분 |
| 음성 채널 | 주요 음성 조작에 원형 버튼 사용. 입력·연결 상태가 바뀔 때만 필요한 피드백 제공 |
| 여행 기록 | 같은 제목·본문 크기와 간격으로 목록 구성. 날짜와 설명은 보조 정보로 표시 |
| 그룹 생성·설정 | 크림색 배경과 웜화이트 패널, 작은 곡률의 입력·선택 컨트롤 재사용 |

새로운 오류·경고·성공 전용 색상과 야간 팔레트는 이 버전에서 정하지 않았습니다. 필요할 때 공통 규칙으로 정의하고 문서에 함께 반영합니다.

## 10. 작업 전달과 검수

작업자는 이 문서와 최신 HTML을 함께 확인합니다. 기존 PNG·JPG는 이전 디자인일 수 있으므로 현재 디자인의 기준으로 삼지 않습니다.

1. 새 화면의 핵심 행동과 정보 순서를 정합니다.
2. 이 문서의 색상·글자·간격·기존 컴포넌트를 적용합니다.
3. 기본·선택·비활성·누름·로딩·오류 등 필요한 상태를 만듭니다.
4. 전체 창과 분할 창에서 배치와 문구를 검수합니다.
5. HTML을 `app/src/main/assets/route-recommendation.html`에 동기화하고 기기에서 글자·조작 영역·기능을 확인합니다. `node docs/design/verify-native-adapter.cjs`로 기준 HTML과 앱에 포함한 파일이 같은지도 확인합니다.

### 검수 체크리스트

- [ ] 배경·표면·본문·보조 글자에 지정된 색상을 사용했는가?
- [ ] 첫 화면에서 핵심 행동을 바로 찾을 수 있는가?
- [ ] 제목과 설명이 중복되거나 큰 안내 카드가 불필요하게 늘어나지 않았는가?
- [ ] 입력과 대화의 곡률은 41px로 같은가?
- [ ] 아이콘의 크기·선 두께·스타일이 일치하는가?
- [ ] 버튼의 누름 피드백과 실행 시점이 일치하는가?
- [ ] 토글은 클릭과 드래그 모두 한 번씩만 상태를 바꾸는가?
- [ ] 그룹 정보가 들어오고 나갈 때 글자와 배치가 갑자기 끊기지 않는가?
- [ ] 그룹원이 그룹 이름 아래 보조 글자색으로 표시되는가?
- [ ] 현재 위치·남은 경유지·목적지가 경로 패널에서 순서대로 표시되는가?
- [ ] 처음에는 경로가 비어 있고, OFF 목록을 받는 것만으로 현재 경로가 바뀌지 않는가?
- [ ] ON 전송의 답변 로딩 3초 후 반영 로딩 2초를 거쳐 경로가 표시되는가?
- [ ] OFF 목록 선택도 2초 반영 로딩을 거치고, 반영 중에는 기존 경로·빈 상태 안내가 숨겨지는가?
- [ ] 모드 전환·과거 답변 복원은 현재 경로를 유지하며, 새로고침 후 선택·대기 상태가 복원되는가?
- [ ] 개인·그룹 양방향에서 다른 모드의 경로를 바꿀 때만 확인 팝업이 나타나는가?
- [ ] 현재 경로 제목 아래에 `개인` 또는 그룹 별칭이 표시되고, 탭 전환·변경 거절·새로고침 후에도 올바른 소속을 유지하는가?
- [ ] 수락과 10초 만료는 2초 반영 로딩으로 이어지고, 거절·Escape 후에는 기존 경로가 유지되는가?
- [ ] 확인 팝업을 새로고침해도 남은 시간이 이어지며, 로딩 중 모드 전환이 요청의 소속을 바꾸지 않는가?
- [ ] 로딩에서 답변으로 바뀔 때 본문이 부드럽게 나타나는가?
- [ ] 긴 그룹 이름·메시지와 분할 창에서도 글자·버튼이 겹치지 않는가?
- [ ] 개인·그룹 전환 후 초안과 대화 범위가 올바른가?
- [ ] 아이콘 버튼의 접근성 이름, 키보드 포커스, 숨긴 요소의 접근 상태가 올바른가?
- [ ] 동작 줄이기 설정에서도 조작과 상태 파악이 가능한가?

### 기준 파일

- [실행 가능한 기준 디자인](route-recommendation.html): 시각 요소와 상호작용의 원본.
- [전체·분할 창 검수 도구](review.html): 동일한 HTML을 두 크기로 비교.
- [동작 확인 스크립트](verify-route-recommendation.cjs): 입력·전송·음성·토글·그룹 전환 등 기존 동작 확인.

로컬 확인 방법은 프로젝트 루트에서 다음과 같습니다.

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/design
```

브라우저에서 `http://127.0.0.1:8765/review.html`을 엽니다. 동작 검사는 `node docs/design/verify-route-recommendation.cjs`로 실행합니다.

공통 디자인 규칙을 바꿀 때는 이 문서와 기준 HTML을 같은 작업에서 갱신합니다. 다른 작업자에게는 두 파일을 함께 전달합니다.
