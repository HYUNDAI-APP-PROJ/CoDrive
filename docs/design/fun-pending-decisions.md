# 차량 간 엔터 요소 · 임시 결정 목록

팀 확인 전에 작업을 진행하려고 임시로 정한 기준입니다. 담당 화면은 `fun-stop-games.html`(룰렛·사다리), `fun-challenges.html`(도전과제), `trip-card.html`(여행 기록 카드)입니다.

- 항목마다 **현재 임시 결정 / 팀 확인 필요 / 바꿀 때 수정할 위치**를 적습니다.
- 새로 임시 결정한 것이 생기면 이 파일 끝에 계속 추가합니다. 팀이 확정하면 "확정"으로 옮기고 날짜를 적습니다.
- 수정할 위치를 바꾼 뒤에는 표시된 검사 스크립트를 다시 실행합니다.

검사 실행(프로젝트 루트):

## 안전·잠금

### 1. 게임(룰렛·사다리) 잠금 해제 조건
- **현재 임시 결정:** 다음 중 하나이고 차량이 STOPPED일 때만 사용할 수 있습니다. 주행 상태를 알 수 없으면(UNKNOWN, NO_DATA, STALE 등) 잠급니다.
  - (a) 경유지 또는 목적지에 도착한 상태
  - (b) STOPPED가 **120초** 이상 유지된 상태

  (a)도 STOPPED일 때만 인정해서, 도착 표시가 남은 채 다시 출발한 경우를 막습니다. 게임 도중 잠기면 그 자리에서 멈추고 결과를 확정하지 않습니다.
- **팀 확인 필요:**
  - 120초가 적절한지
  - 기어 P단 정보를 받을 수 있는지. 받을 수 있으면 `parked` 조건을 추가합니다.

  차량 상태 담당과 확인합니다.
- **바꿀 때 수정할 위치:** `js/play-safety.js`의 `STOP_HOLD_SECONDS`와 `getPlaySafety()`. P단 조건은 같은 파일의 "기어 상태 필드 추가 시 parked 조건 추가" 주석 자리에 넣습니다.

### 2. 주행 상태가 오래된 값으로 보는 기준
- **현재 임시 결정:** 주행 상태(motion)가 **5초**보다 오래되면 STALE로 낮춰 잠금 판단에 쓰지 않습니다.
- **팀 확인 필요:** 실제 Vehicle SDK의 갱신 주기
- **바꿀 때 수정할 위치:** `js/vehicle.js`의 `MOTION_STALE_MS`

## 메뉴·진입

### 3. 화면 위치와 사이드 메뉴
- **현재 임시 결정:** 사이드 메뉴 항목은 바꾸지 않습니다.
  - 도전과제와 여행 카드는 "여행 기록" 아래 화면이고, "여행 기록"을 선택 상태로 표시합니다.
  - 룰렛·사다리는 메뉴 없이 진입하며, 선택된 메뉴가 없습니다.
- **팀 확인 필요:**
  - 룰렛·사다리 진입 경로(그룹 화면 담당)
  - "여행 기록" 아래에서 도전과제와 여행 카드를 오가는 방법(탭 등)
- **바꿀 때 수정할 위치:** 각 HTML의 `<nav class="nav">` 안 `.nav-item`. 선택 표시는 `active` 클래스와 `aria-current="page"`입니다.

### 4. 게임 참여 조건
- **현재 임시 결정:** 그룹 차량 **2대 이상**일 때만 게임을 보여줍니다. 참여 차량은 그룹 전체이고, 연결 상태와 관계없이 차량 별칭으로 표시합니다. 그룹이 없으면 안내만 보여줍니다.
- **팀 확인 필요:** 연결이 끊긴 차량을 참여 대상에서 뺄지(그룹 담당)
- **바꿀 때 수정할 위치:** `fun-stop-games.html`의 `renderGroup()`

## 도전과제 기준

### 5. 쉬어가는 여행
- **현재 임시 결정:** 연속 운전 **2시간**이 되기 전에 **15분** 이상 휴식하면 달성입니다(한국도로공사 권장 기준).
  - 주행 중에는 달성을 판정하지 않습니다. 지난 휴식 앞의 운전 시간을 알 수 없기 때문입니다.
  - 2시간을 넘기면 "이번엔 놓쳤어요"로 표시하고, 다음 운전 구간에서 다시 도전할 수 있습니다.
- **팀 확인 필요:** 신호 대기 같은 짧은 정차도 "휴식"으로 세는지는 SDK의 연속 운전 시간 계산 방식에 달려 있습니다(7번).
- **바꿀 때 수정할 위치:** `js/challenge-rules.js`의 `RULES.REST_MAX_DRIVING_SECONDS`, `RULES.REST_MIN_SECONDS`, `evaluateRest()`

### 6. 부드러운 운전
- **현재 임시 결정:** 이번 여행에서 **20km** 이상 달린 뒤, 내 차량의 현재 연비가 공인 연비의 **105%** 이상이면 달성입니다.
  - 20km 미만이면 연비와 관계없이 "진행 중"입니다.
  - 전기차는 전비(km/kWh)로 판정합니다.
  - 다른 차량과 비교하지 않습니다.
- **팀 확인 필요:**
  - 105%와 20km가 적절한지
  - "현재 연비"가 여행 평균인지 순간값인지(차량 상태 담당)
- **바꿀 때 수정할 위치:** `js/challenge-rules.js`의 `RULES.EFFICIENCY_TARGET_RATIO`, `RULES.EFFICIENCY_MIN_DISTANCE_KM`

### 7. 완벽한 합류 · 만장일치 · 또 만났네요
- **현재 임시 결정:**
  - **완벽한 합류:** 그룹 전원이 장소 종류가 `REST_AREA`인 같은 장소에 도착하면 달성입니다. 한 차량이라도 도착 정보를 알 수 없으면 "확인할 수 없어요"입니다. 화면에는 대수만 보여주고 차량 이름은 보여주지 않습니다.
  - **만장일치:** 여행이 **끝나야** 확정합니다. 룰렛·사다리는 투표가 아니므로 제외합니다. 투표가 0건으로 끝나면 놓침입니다.
  - **또 만났네요:** 같은 그룹과 **3번째** 여행이면 달성입니다.
- **팀 확인 필요:** 투표가 없었던 여행의 만장일치 처리, 3번째 기준
- **바꿀 때 수정할 위치:** `js/challenge-rules.js`의 `evaluateMerge()`, `evaluateUnanimous()`, `RULES.REUNION_TRIP_NUMBER`

### 8. 판정 불가와 알림 시점
- **현재 임시 결정:**
  - 판정에 필요한 값이 AVAILABLE이 아니면, 값이 남아 있는 STALE이라도 "확인할 수 없어요"로 둡니다.
  - 달성은 즉시 여행 기록에 남깁니다.
  - 새 달성 알림은 쌓아 두었다가 `isSafeToPlay()`가 true일 때 보여주고, 다시 주행하면 숨깁니다.
- **팀 확인 필요:** 알림을 음성(TTS)으로도 알릴지(음성 담당)
- **바꿀 때 수정할 위치:** `js/challenge-rules.js`의 `usable()`, `fun-challenges.html`의 `refresh()`와 `renderNotice()`

## 데이터 출처와 의미

### 9. `drivingSeconds`의 의미
- **현재 임시 결정:** vehicle-status-ui 모델의 `drivingSeconds`를 "마지막 휴식 이후 연속 운전 시간"으로 보고 사용합니다.
- **팀 확인 필요:** 실제 의미가 "여행 전체 주행 시간"인지(차량 상태 담당). 전체 주행 시간이라면 연속 운전 시간 필드를 따로 추가해야 합니다.
- **바꿀 때 수정할 위치:** `js/vehicle.js`의 `getContinuousDrivingSeconds()`

### 10. `tripDistance`의 단위
- **현재 임시 결정:** 모델의 `tripDistance`를 **km**로 보고, 연비 과제 최소 거리 판정에 사용합니다.
- **팀 확인 필요:** 단위가 m인지 km인지(차량 상태 담당)
- **바꿀 때 수정할 위치:** `js/vehicle.js`의 `getTripDistance()`(단위 변환 추가)

### 11. 모델에 없어서 추가 예정으로 둔 차량 필드
- **현재 임시 결정:** `vehicle.js`가 다음 이름으로 값을 제공합니다. 지금은 시연 데이터입니다.
  - `motionHeldSeconds`: 현재 주행 상태가 유지된 시간
  - `lastRestSeconds`: 가장 최근 정차 길이
  - `fuelEfficiency`, `ratedFuelEfficiency`: 현재·공인 연비(전기차는 전비)
- **팀 확인 필요:** 모델(`VehicleStatus`)에 같은 이름으로 추가할 수 있는지. `motionHeldSeconds`는 SDK가 주지 않으면 앱이 상태가 바뀐 시각을 기억해 계산합니다.
- **바꿀 때 수정할 위치:** `js/vehicle.js`의 "데이터 출처" 구역(`readRaw()`)

### 12. 경유지·목적지 도착과 현재 경로
- **현재 임시 결정:**
  - 도착 여부는 `js/navi.js`의 `getArrivalState()`에서만 가져옵니다(NaviHelper 도착 이벤트로 교체 예정).
  - 현재 경로 패널은 같은 파일의 `getActiveRoute()`로 그립니다(NaviHelper `getRouteStateInfo`로 교체 예정).
  - 추천 화면의 내부 저장값은 읽지 않습니다.
- **팀 확인 필요:** NaviHelper 이벤트·응답 형식, 내비 연동 담당과의 역할 분담
- **바꿀 때 수정할 위치:** `js/navi.js`의 "데이터 출처" 구역

### 13. 장소 종류 `placeCategory`
- **현재 임시 결정:** 그룹 차량의 도착 정보에 장소 종류(`REST_AREA` 등)를 넣고, "같은 휴게소" 판정에 사용합니다.
- **팀 확인 필요:** 실제 장소 종류를 어디서 받을지(그룹 담당, 내비·추천 담당)
- **바꿀 때 수정할 위치:** `js/group.js`의 `toVehicle()`, 시연 값은 `js/mock-scenario.js`의 `PLACES`

### 14. 투표 집계 `votes { agree, total }`와 가결 기준
- **현재 임시 결정:** 투표(VOTE) 결정은 찬성 수를 함께 기록합니다(`tripLog.recordDecision({ kind: 'VOTE', votes })`).
  - 여행 카드에서는 **찬성이 과반이면 가결**로 표시합니다.
  - 집계가 없는 투표는 "집계 없음"으로 표시하고, 만장일치 판정에서는 "확인할 수 없어요"입니다.
- **팀 확인 필요:**
  - 실제 투표 결과를 누가 기록할지(그룹 공동 의사결정 담당)
  - 리더 결정이나 전원 수락 방식의 투표에서 가결을 어떻게 표시할지. README의 결정 방식이 여러 가지라 과반 기준이 맞지 않을 수 있습니다.
- **바꿀 때 수정할 위치:** `js/trip-log.js`의 `recordDecision()`, `trip-card.html`의 `passed()`

### 15. 같은 그룹과의 여행 횟수 `getTripNumberWithGroup()`
- **현재 임시 결정:** `trip-log.js`가 시연 값 **3**을 돌려줍니다. 시연 때는 주소의 `?trip=1~10`이나 시연 패널 버튼으로 바꿉니다.
- **팀 확인 필요:** 실제 여행 기록 저장소에서 계산하는 방법(history 담당)
- **바꿀 때 수정할 위치:** `js/trip-log.js`의 `getTripNumberWithGroup()`, `seed()`

### 16. 여행 기록 저장 위치와 "함께한 시간"
- **현재 임시 결정:**
  - 여행 기록은 브라우저 탭의 `sessionStorage`(`codrive.history.trip-log.v1`)에만 저장합니다. 탭을 닫으면 사라집니다.
  - "함께한 시간"은 여행 시작부터 종료(진행 중이면 현재)까지입니다.
- **팀 확인 필요:** history 저장소 형식, 여행 종료 조건, 그룹 해산과의 관계(README 6절의 미정 사항)
- **바꿀 때 수정할 위치:** `js/trip-log.js`(공개 함수 이름과 반환 형식은 유지하고 내부만 교체)

## 화면·시연

### 17. 여행 카드의 QR 코드
- **현재 임시 결정:** 완성된 카드에 QR 코드 **자리만** 두고 "시연용"으로 표시합니다. 실제 QR은 만들지 않습니다.
- **팀 확인 필요:** 휴대폰 저장·공유 방식(링크, 이미지 등)과 서버 필요 여부
- **바꿀 때 수정할 위치:** `trip-card.html`의 `<section class="save">`

### 18. 시연 패널
- **현재 임시 결정:** 주소에 `?dev=1`이 있을 때만 보입니다. 제공하는 기능은 다음과 같습니다.
  - 시나리오 8개 전환
  - 연속 주행 1시간 59분으로 점프
  - 같은 그룹 여행 1·2·3번째 선택(누르면 시연 기록을 처음부터 다시 시작)
  - 여행 종료 처리
  - 시연 초기화

  `dev=1`이 없으면 아무것도 하지 않습니다(검사로 확인).
- **팀 확인 필요:** 앱 배포 화면에서 이 파일을 뺄지(포팅 담당)
- **바꿀 때 수정할 위치:** `js/dev-panel.js`, 각 HTML의 `<script src="js/dev-panel.js">`

## 포팅·검사

### 19. 앱에서 스크립트를 불러오는 방식
- **현재 임시 결정:** 미정입니다.
  - 지금 화면은 `js/*.js`를 `<script src>`로 불러옵니다.
  - 현재 앱(`MainActivity`)은 HTML을 `loadDataWithBaseURL`에 문자열로 넘기므로, 이 파일들을 찾지 못합니다.
- **팀 확인 필요:** 스크립트를 HTML 안에 끼워 넣을지, `WebViewAssetLoader` 등으로 assets 파일을 읽게 할지. 8단계에서 포팅 담당과 정합니다.
- **바꿀 때 수정할 위치:** 각 HTML 아래쪽의 `<script src>`, `app/src/main/java/com/codrive/app/MainActivity.java`

### 20. 화면 검사의 브라우저 의존성
- **현재 임시 결정:** 화면 검사 스크립트는 헤드리스 Chrome이나 Edge가 있어야 실행됩니다. 추가 패키지는 없습니다. 브라우저 경로는 `CHROME_PATH`로 바꿀 수 있습니다.
- **팀 확인 필요:** CI에서 실행할지, 실행한다면 브라우저를 설치할지
- **바꿀 때 수정할 위치:** `lib/browser-harness.cjs`의 `findBrowser()`
